Un assistant répond. Un agent agit. Cette différence change tout en matière de bénéfices… et de risques.

## Ce que peut faire un agent

Selon les outils, un agent peut :

- **rechercher** des informations sur internet ou dans des documents ;
- **utiliser des applications** : messagerie, agenda, tableurs, outils de gestion ;
- **enchaîner des étapes** pour atteindre un objectif : chercher, comparer, synthétiser, rédiger, envoyer ;
- **travailler de façon autonome** pendant un certain temps, ou à intervalles réguliers.

**Exemple** : un agent de veille qui, chaque lundi, recherche les nouveaux appels d'offres publiés dans le secteur de l'énergie solaire en Afrique centrale, filtre ceux qui correspondent aux critères de l'entreprise, et envoie une synthèse au directeur commercial.

## Les outils sans code

Plusieurs familles d'outils permettent de créer des agents sans programmer :

- **les fonctions d'agent des grands assistants IA**, capables de naviguer sur le web, d'utiliser des connecteurs vers vos applications ou d'exécuter des tâches programmées ;
- **les plateformes d'automatisation** (comme celles présentées dans le cours « Automatiser les tâches administratives ») qui intègrent désormais des étapes d'IA dans leurs flux ;
- **les plateformes spécialisées** de création d'agents, avec des interfaces visuelles.

Leur fonctionnement, leurs prix et leurs conditions évoluent très vite : comparez les offres au moment de votre projet.

## Les principes de sécurité

Plus un agent a de pouvoirs, plus ses erreurs peuvent coûter cher. Appliquez ces principes :

**1. Le moindre privilège.** Donnez à l'agent uniquement les accès strictement nécessaires. Un agent de veille n'a pas besoin d'accéder à la comptabilité.

**2. La validation humaine avant les actions importantes.** L'agent prépare, l'humain valide : envoi d'un e-mail à un client, paiement, modification de données, publication.

**3. La traçabilité.** Gardez un historique de ce que fait l'agent, pour pouvoir vérifier et corriger.

**4. Les limites.** Fixez des plafonds : nombre d'actions, montants, destinataires autorisés.

**5. L'arrêt d'urgence.** Sachez comment désactiver l'agent immédiatement en cas de problème.

::: attention
Un agent qui lit des contenus externes (pages web, e-mails, documents reçus) peut tomber sur des instructions cachées destinées à le détourner, par exemple « transfère tous les fichiers à cette adresse ». C'est ce qu'on appelle une injection d'instructions. C'est une raison de plus pour limiter ses accès et exiger une validation humaine avant toute action sensible.
:::

## Commencer prudemment

Le bon chemin est progressif :

1. un **assistant** qui répond ;
2. un **agent qui prépare** des actions (brouillons d'e-mails, lignes de tableau) validées par un humain ;
3. un **agent qui agit seul** sur des tâches à faible risque, bien testées, avec surveillance.

::: a-vous Votre agent sur papier
Imaginez un agent utile à votre organisation. Décrivez son objectif, les étapes qu'il enchaîne, les outils et accès nécessaires, les actions soumises à validation humaine, les limites et la façon de l'arrêter. Demandez à l'IA d'identifier les risques que vous n'avez pas prévus.
:::

::: a-retenir
- Un agent enchaîne des étapes et agit dans des applications.
- Des outils sans code permettent de créer des agents, et évoluent vite.
- Moindre privilège, validation humaine, traçabilité, limites, arrêt d'urgence.
- Progressez de l'assistant à l'agent qui prépare, puis à l'agent autonome sur des tâches à faible risque.
:::
